# JotFolio Review

Would I keep using this product today? Yes, but only because the local Markdown vault, Notes workspace, Search, Inbox, Graph Health direction, and recovery pieces are worth fighting for. I would not trust the whole app yet, because too many surfaces still act like product claims before the workflow is tight. The app needs to stop adding screens and finish the daily loop: capture, process, write, relate, recover.

## REMOVE

1. AI Setup main route - it says chat is not ready, so it does not belong in main nav.
2. Notifications bell - it routes to Inbox and has no notification model.
3. Podcast capture type - generic note form with a podcast icon.
4. Video capture type - generic note form with a video icon.
5. Attachment tab - promises an attachment system the UI does not fully expose.
6. Compile raw to memory in Inbox - too advanced beside ordinary sorting.
7. Command Center session goals / priorities / reflection copy - fake productivity language.
8. Command Center capture-mode quick composer - duplicates Capture.
9. Command Center planning / review panels - dashboard filler unless they mutate real work.
10. Project Smart View shortcut - adds mental overhead before Bases are clear.
11. Calendar graph/link/review action cluster - day detail is too crowded.
12. Semantic edges / MiniLM suggestions - hide until review cards and undo are airtight.
13. Split memory modal in normal UI - too early for the current product.
14. Appearance theme sprawl - too many knobs while workflows still need finishing.
15. Extensions panel - hide until plugin install/use is real for normal users.
16. Public npm scripts as product surface - developer tools, not user features.

## One Thing Before Another Feature

Fix the end-to-end daily loop before adding anything else: blank vault onboarding, Capture, Inbox processing, Notes editing, Search retrieval, Graph Health review, Trash/recovery. If that loop is not fast, obvious, and safe, every new surface just gives the user another way to lose trust.
